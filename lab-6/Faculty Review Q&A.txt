Q1. What is the role of URLSession?
Answer:
`URLSession` is Apple's high-level networking API responsible for coordinating network data transfer tasks between an iOS app and remote endpoints. 
Key responsibilities include:
1. Managing HTTP/HTTPS requests, headers, query parameters, and caching policies.
2. Handling background and concurrent connection pooling efficiently.
3. Providing modern asynchronous Swift concurrency APIs (`session.data(for: request)`) that pause the calling task without blocking the main UI thread.
4. Returning both raw response `Data` and metadata (`URLResponse` / `HTTPURLResponse`) containing headers and HTTP status codes.

Q2. Why use Codable instead of manually reading dictionary keys?
Answer:
`Codable` (specifically `Decodable`) provides type-safe, compile-time checked conversion from raw JSON data into native Swift struct or class instances.
Reasons to use Codable over manual NSDictionary / [String: Any] parsing:
1. Type Safety: Property types (Int, String, nested structs) are strictly validated by the compiler and runtime.
2. Less Boilerplate: Automatically synthesizes decoding logic without writing tedious type-casting (`json["name"] as? String`).
3. Compiler Errors vs Runtime Crashes: In manual dictionary reading, a typo in a string key fails silently at runtime. With `CodingKeys`, errors are caught reliably.
4. Performance & Cleanliness: `JSONDecoder` is highly optimized in Swift and produces clean, maintainable domain models.

Q3. What should the app do when the server returns HTTP 404 or 500?
Answer:
1. Check Status Code: The app must inspect `(response as? HTTPURLResponse).statusCode` before attempting to decode data.
2. HTTP 404 (Not Found): 
   - Indicates the requested endpoint or resource no longer exists.
   - The app should inform the user gracefully with a localized message (e.g., "The requested directory item was not found on the server").
   - It should offer a "Back" or "Refresh" action, avoiding an unhandled crash or blank screen.
3. HTTP 500 (Internal Server Error):
   - Indicates a server-side crash or service downtime.
   - The app should display a polite, non-technical error view ("Server is currently unavailable, please try again shortly").
   - It must provide a prominent "Retry Request" button so the user can easily re-attempt once the backend recovers, possibly with an exponential backoff.

Q4. How would you avoid exposing API keys in a mobile app?
Answer:
Because compiled iOS binaries can be inspected and reverse-engineered (using tools like `strings` or disassemblers), hardcoding API keys in source code is unsafe.
Best practices to avoid exposing keys:
1. Backend Proxy / BFF (Backend for Frontend): Route app network calls through your own secured backend server. The app authenticates using session tokens (OAuth / JWT), and the backend attaches the secret API keys to upstream services.
2. Xcode Configuration (.xcconfig) & Secrets Management: Store keys in a `.xcconfig` or local environment file that is listed in `.gitignore` and injected during CI/CD build pipelines.
3. Keychain Services: Store user-specific authentication tokens securely in the encrypted iOS Keychain.
4. Certificate Pinning / App Attest: Use Apple's DeviceCheck and App Attest APIs to ensure only genuine, unmodified instances of your app can reach backend endpoints.

Q5. How would you test decoding without depending on a live API?
Answer:
1. Dependency Injection with Protocols: Define a protocol (e.g., `UserServiceProtocol`) and inject a `MockUserService` into view controllers or test suites.
2. Bundled JSON Fixtures: Save sample JSON response files (e.g., `users_sample.json`, `empty_users.json`, `malformed_users.json`) directly in the test bundle.
3. Direct `JSONDecoder` Unit Testing: Pass local JSON `Data(sampleString.utf8)` directly to `JSONDecoder().decode([User].self, from: data)` to verify that models decode correctly without any network connection.
4. Custom `URLProtocol`: Subclass `URLProtocol` to intercept network requests and return stubbed HTTP responses and canned JSON data synchronously and deterministically.
